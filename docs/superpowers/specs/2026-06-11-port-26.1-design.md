# Design: Port Emerald Economy 1.21.11 → Minecraft 26.1.2

**Date:** 2026-06-11
**Status:** Approved
**Approach:** Direct single-jump port on a branch (Approach A)

## Context

Minecraft moved to a new version numbering scheme; the latest stable release is
**26.1.2** ("Tiny Takeover"). 26.2 ("Chaos Cubed") releases 2026-06-16 and is a
separate follow-up bump, not part of this work. Yarn mappings are discontinued
after 1.21.11 — the Fabric toolchain now defaults to Mojang's official mappings,
so the port includes a full yarn→mojmap rename of the codebase (40 Java files,
~3,800 lines).

## Goal

The mod compiles, its unit tests pass, and a dev server on 26.1.2 runs the full
economy loop (accounts, shop GUIs, buy/sell, rewards, SQLite persistence) with
behavior identical to 1.5.1 on 1.21.11.

## 1. Branch & versioning

- Branch: `port/26.1` off `master`.
- `mod_version = 1.6.0-26.1.2` (minor bump: same features, new platform).

## 2. Build toolchain changes

`gradle.properties` / `build.gradle`:

| Property | From | To |
|---|---|---|
| minecraft_version | 1.21.11 | 26.1.2 |
| yarn_mappings | 1.21.11+build.6 | **removed** (Loom 1.16 defaults to Mojang official mappings; matches the current fabric-example-mod, which declares no mappings) |
| loom_version | 1.14-SNAPSHOT | 1.16-SNAPSHOT |
| fabric_version | 0.141.4+1.21.11 | 0.151.0+26.1.2 |
| loader_version | 0.19.3 | 0.19.3 (unchanged) |
| sgui | 1.12.0+1.21.11 | 2.0.0+26.1 |
| fabric-permissions-api | 0.6.0 | 0.7.0 |
| common-economy-api | 1.1.1 | 2.0.0 |
| savdbcore | 1.2.0 | 1.3.1 (jitpack tag `1.3.1`, declares MC `>=1.20`) |

- The `mappings` dependency line in `build.gradle` is dropped.
- HikariCP/Caffeine remain `compileOnly`; versions re-checked against what
  savdbcore 1.3.1 actually bundles.
- JAR-in-JAR `include` lines keep mirroring the `modImplementation` versions
  for all four bundled deps.

## 3. Mappings migration (yarn → Mojang official)

- Rename driven by compiler errors across all 40 files. Known high-frequency
  renames: `ServerPlayerEntity`→`ServerPlayer`, `Text`→`Component`,
  `Identifier`→`ResourceLocation`, `ServerCommandSource`→`CommandSourceStack`,
  `PlayerEntity`→`Player`. The compiler is the checklist; no rename is done
  speculatively.
- Access widener rewritten to mojmap names, staying minimal at exactly one
  entry: `accessible field net/minecraft/server/level/ServerPlayer server
  Lnet/minecraft/server/MinecraftServer;` (exact owner/descriptor verified at
  implementation time against the 26.1.2 mojmap).
- `fabric.mod.json`: `"minecraft": "~26.1"`.

## 4. Real API changes (after renames compile)

- **sgui 2.0** (major version): update the `gui/` classes per sgui's 2.0
  migration notes/changelog — read at implementation time, do not guess.
- **common-economy-api 2.0** (major version): update `integration/`
  (`EmeraldEconomyProvider`, `Account`, `Currency`) the same way. Provider id
  `emerald_economy` and currency id `emerald_economy:dollar` are unchanged.
- **MC API churn** (commands, registries, items, events) between 1.21.11 and
  26.1.2: fix what the compiler and dev server surface.
- **Invariants preserved unchanged:**
  - Optimistic-locking balance writes (`addBalance`/`removeBalance` with
    version retry; versionless `setBalance` stays admin-only).
  - Debit-first / refund-on-failure in `transfer` and all money paths.
  - `TradeService` remains the single buy/sell transaction path.
  - `ShopDropGuis.settleOnDisconnect` wiring (sgui `onClose` still doesn't
    fire on abrupt disconnect — re-verify this assumption against sgui 2.0).

## 5. Risk ordering — savdbcore first

savdbcore 1.3.1 is the only dependency with no published 26.x build. As soon as
the project first compiles, boot `runServer` and exercise a balance read/write
to confirm SQLite storage works **before** any GUI work. If it fails, stop and
flag it: porting savdbcore is a separate sub-project.

## 6. Verification

1. `./gradlew test` — pure-logic suite passes (PriceBook, DailyRewards,
   PlaytimeIncome, DailyCommand).
2. `./gradlew build` — clean jar containing all four bundled (`include`) deps.
3. `./gradlew runServer` smoke pass: join → account auto-created; `/balance`;
   `/shop` hub and Buy/Sell/Deposit/Withdraw/Transfer/TopBalances GUIs;
   `/buy` + `/sell`; `/daily`; `/eco reload`; disconnect with an open drop-GUI
   and confirm settlement on rejoin; `/ecolog` shows the audit trail.
4. Existing `worth.json` loads as-is (1.21.x item ids remain valid; new 26.x
   items stay unlisted = not tradeable, which is the safe whitelist default).

## 7. Out of scope

- Pricing new 26.x content (`/eco generateprices` → `extract.py` → `derive.py`
  → `arbitrage.py` pass) — separate follow-up.
- The 26.2 ("Chaos Cubed") bump on 2026-06-16.
- Production server deployment and world upgrade. Deployment note: back up the
  world and `economy_data.sqlite` before first 26.1.2 boot.
